# dw v2 — Diff Direct Writer (Windows)

فایل `diff.txt` را باز می‌کند، **خط اول** را به‌عنوان آدرس ریپو می‌خواند و بقیه‌ی فایل (diff) را روی همان ریپو، **فایل به فایل** اعمال می‌کند. ریپو می‌تواند روی هر درایو (C:، D:، ...) باشد.

## محتویات

| فایل | کاربرد |
|---|---|
| `diff.txt` | diff را اینجا بریزید (خط اول = مسیر ریپو) |
| `apply.cmd` | **دوبار کلیک** = اجرا (و بعد پنجره باز می‌ماند تا نتیجه را ببینید) |
| `dw.cmd` | اجرا از CMD / PowerShell با گزینه‌ها |
| `dw-core.ps1` | نسخه‌ی اصلی PowerShell (از طریق `dw.cmd` اجرا می‌شود) |
| `dw.sh` | نسخه‌ی Bash برای Git Bash / WSL (همان رفتار) |

پیش‌نیاز: **Git for Windows** و PowerShell 5.1 (از قبل روی ویندوز 10/11 هست). نصب جداگانه لازم نیست.

## روش کار (۳ مرحله)

1. پوشه‌ی `dw-windows` را **هر جای دیسک** بگذارید (مثلاً `D:\tools\dw`).
2. `diff.txt` را با Notepad باز کنید:
   - **خط اول:** مسیر ریپو، مثلاً `C:\code\esmaeil-ahmadipour-portfolio`
   - **از خط دوم به بعد:** diff را paste کنید. ذخیره کنید.
3. روی **`apply.cmd` دوبار کلیک** کنید.

مثال `diff.txt`:

```
D:\projects\esmaeil-ahmadipour-portfolio
diff --git a/src/App.jsx b/src/App.jsx
--- a/src/App.jsx
+++ b/src/App.jsx
@@ -1,3 +1,3 @@
 ...
```

برنامه `diff.txt` را **کنار خودش** پیدا می‌کند، مهم نیست از کجا اجرایش کنید (اگر آنجا نبود، `diff.txt` پوشه‌ی جاری). می‌توانید فایل دیگری هم بدهید: `dw C:\somewhere\other-diff.txt`

اختیاری: پوشه را به PATH اضافه کنید تا از هر ترمینال فقط `dw` بزنید (به شرط اینکه `diff.txt` کنار همین پوشه باشد).

## چه اتفاقی می‌افتد

1. مسیر ریپو و لیست فایل‌ها نشان داده می‌شود (`[NEW]`, `[MOD]`, `[DEL]`, `[REN]`).
2. **یک بار** می‌پرسد `Apply these changes to this repo? [Y/n]`. فقط Enter یا `y` بزنید. برای نپرسیدن: `-y`.
3. هر فایل جدا بررسی و اعمال می‌شود و فایلی که مشکل داشته باشد بقیه را متوقف نمی‌کند:
   - `[ OK ]` اعمال شد
   - `[SKIP]` قبلاً اعمال شده بود (اجرای دوباره بی‌خطر است)
   - `[FAIL]` اعمال نشد، همراه دلیل
4. در پایان خلاصه: `Done: X applied, Y skipped, Z failed`.

برای فایل‌های `FAIL` محتوای فعلی همان فایل‌ها را برای Claude بفرستید تا diff تازه بسازد.

## وقتی محتوای فایل مقصد فرق دارد (رفتار پیش‌فرض)

فایلی که محتوایش با diff نمی‌خواند `[FAIL]` می‌شود و دلیلش چاپ می‌شود. آن فایل **دست‌نخورده** می‌ماند و بقیه‌ی فایل‌ها اعمال می‌شوند. در پایان خلاصه می‌دهد: `Done: X applied, Y skipped, Z failed`. اگر همه‌یا‌هیچ می‌خواهید، `-s` بزنید.

| شرایط | نتیجه (فقط برای همان فایل، بقیه ادامه می‌دهند) |
|---|---|
| خطوط diff با فایل نمی‌خواند | `[FAIL]` |
| فایل در مقصد وجود ندارد (diff برای تغییر است) | `[FAIL]` |
| diff می‌گوید فایل جدید، ولی از قبل هست | `[FAIL]`، رویش نمی‌نویسد |
| diff می‌گوید حذف، ولی محتوا فرق دارد | `[FAIL]`، پاک نمی‌شود |
| تغییر از قبل اعمال شده | `[SKIP]` |
| فقط فاصله یا CRLF فرق دارد | اعمال می‌شود، با علامت `(whitespace-tolerant)` |
| تفاوت در جای دیگر فایل (بیرون از بلوک‌ها) | مشکلی نیست؛ جای بلوک با متن اطرافش پیدا می‌شود، نه شماره‌ی خط |
| مسیر ریپو غلط یا ریپو نیست | هیچ‌چیز اعمال نمی‌شود، خطا |
| خط اول مسیر نیست، diff است | هیچ‌چیز اعمال نمی‌شود، خطا |

اگر در یک فایل چند بلوک باشد و یکی نخواند، کل آن فایل `[FAIL]` می‌شود (فایل هرگز نیمه‌کاره نمی‌ماند). فایلی که اعمال می‌شود فقط خطوط مشخص‌شده را عوض می‌کند، نه کل فایل را. برای ایمنی، اول با `-n` (فقط بررسی) اجرا کنید.

## گزینه‌ها (در CMD / PowerShell با `dw`)

| گزینه | کار |
|---|---|
| `-n` / `-DryRun` | فقط بررسی، چیزی نوشته نمی‌شود |
| `-y` / `-Yes` | بدون پرسیدن تأیید |
| `-s` / `-Strict` | همه یا هیچ: اگر حتی یک فایل مشکل داشت، هیچ‌چیز اعمال نشود |
| `-b NAME` / `-Branch` | قبل از اعمال، branch جدید بساز |
| `-c "MSG"` / `-Commit` | فایل‌های اعمال‌شده را commit کن |
| `-a` / `-Archive` | بعد از اجرای کاملاً موفق، `diff.txt` را به `diff.applied-<تاریخ>.txt` تغییر نام بده |
| `-r PATH` / `-Repo` | به‌جای خط اول از این مسیر استفاده کن |
| `-u` / `-Undo` | آخرین اجرا را برگردان |
| `-Help` | راهنما |

### مثال‌ها

```powershell
.\dw.cmd -n                                 # اول فقط بررسی
.\dw.cmd                                    # اعمال (یک بار تأیید می‌گیرد)
.\dw.cmd -y -b feat/theme -c "Update theme"
.\dw.cmd -u                                 # برگرداندن آخرین اجرا
.\dw.cmd -u -r C:\code\portfolio            # برگرداندن، وقتی diff.txt بایگانی شده
```

در Git Bash همین رفتار با `./dw.sh` است و گزینه‌ها سبک Linux هستند (`-n -y -s -a -b -c -r -u`).

## نکات

- مسیر می‌تواند `C:\...`، `D:\...`، `~\...`، `%USERPROFILE%\...` یا شکل Git Bash (`/c/code/site`) باشد. پیشوند `repo:` هم قبول است. می‌توانید دور مسیر گیومه بگذارید.
- آخرین اجرا در `.git\dw-last.patch` ذخیره می‌شود (commit نمی‌شود). `-u` همان را برمی‌گرداند. اگر با `-c` commit کرده بودید، برای برگشت از `git reset --hard HEAD~1` استفاده کنید.
- تغییرات commit‌نشده‌ی خودتان دست نمی‌خورد؛ فقط هشدار داده می‌شود.
- فنس‌های markdown و متن‌های اضافه‌ی چت خودکار نادیده گرفته می‌شوند. فایل ذخیره‌شده با Notepad (CRLF / BOM / UTF-16) هم مشکلی ندارد.
- اگر فایل‌هایتان CRLF است و diff فقط در پایان خط فرق دارد، برنامه خودکار با تحمل فاصله‌ها اعمال می‌کند و `(whitespace-tolerant)` می‌نویسد.

## عیب‌یابی

- **`repo folder not found`**: خط اول `diff.txt` را بررسی کنید (مثلاً `C:\PUT\YOUR\REPO\PATH\HERE` در فایل نمونه باید عوض شود).
- **`line 1 ... must be the repo path`**: خط اول diff است، نه مسیر. یک خط مسیر بالای diff اضافه کنید.
- **`patch does not apply`**: فایل شما با نسخه‌ای که diff روی آن ساخته شده فرق دارد. فایل فعلی را برای Claude بفرستید.
- **`running scripts is disabled`**: همیشه از `dw.cmd` / `apply.cmd` استفاده کنید، نه مستقیم `dw-core.ps1`. آن‌ها ExecutionPolicy را فقط برای همان اجرا Bypass می‌کنند.
- **Windows SmartScreen هشدار داد**: فایل‌ها متن ساده‌اند و می‌توانید بخوانید. روی ZIP راست‌کلیک ← Properties ← Unblock هم کمک می‌کند.
- **پنجره بلافاصله بسته شد**: با `apply.cmd` اجرا کنید (بعد از اتمام pause دارد) یا از CMD اجرا کنید.
