# dw v2 — Diff Direct Writer (Ubuntu / Linux)

فایل `diff.txt` را باز می‌کند، **خط اول** را به‌عنوان آدرس ریپو می‌خواند و بقیه‌ی فایل (diff) را روی همان ریپو، **فایل به فایل** اعمال می‌کند.

## روش کار (۳ مرحله)

1. پوشه‌ی `dw-linux-ubuntu` را هر جای دیسک بگذارید.
2. فایل `diff.txt` کنار `dw.sh` را باز کنید:
   - **خط اول:** مسیر ریپو، مثلاً `~/code/portfolio` یا `/mnt/d/work/site`
   - **از خط دوم به بعد:** diff را paste کنید
3. اجرا:
   ```bash
   ./dw.sh
   ```

مثال `diff.txt`:

```
~/code/esmaeil-ahmadipour-portfolio
diff --git a/src/App.jsx b/src/App.jsx
--- a/src/App.jsx
+++ b/src/App.jsx
@@ -1,3 +1,3 @@
 ...
```

برنامه هر جا باشد، `diff.txt` را **کنار خودش** پیدا می‌کند (اگر نبود، `./diff.txt` در پوشه‌ی جاری). می‌توانید مسیر دیگری هم بدهید: `./dw.sh /path/to/other-diff.txt`

اختیاری: برای اجرا از هر جا یک alias بسازید:

```bash
echo "alias dw='$PWD/dw.sh'" >> ~/.bashrc
```

## چه اتفاقی می‌افتد

1. مسیر ریپو و لیست فایل‌ها نشان داده می‌شود (`[NEW]`, `[MOD]`, `[DEL]`, `[REN]`).
2. **یک بار** می‌پرسد `Apply these changes to this repo? [Y/n]`. فقط Enter یا `y` بزنید. برای نپرسیدن: `-y`.
3. هر فایل جدا بررسی و اعمال می‌شود و فایلی که مشکل داشته باشد بقیه را متوقف نمی‌کند:
   - `[ OK ]` اعمال شد
   - `[SKIP]` قبلاً اعمال شده بود (اجرای دوباره بی‌خطر است)
   - `[FAIL]` اعمال نشد، همراه دلیل
4. در پایان خلاصه: `Done: X applied, Y skipped, Z failed`.

برای فایل‌های `FAIL` محتوای فعلی همان فایل‌ها را برای Claude بفرستید تا diff تازه بسازد.

## وقتی محتوای فایل مقصد فرق دارد (رفتار پیش‌فرض)

فایلی که محتوایش با diff نمی‌خواند `[FAIL]` می‌شود و دلیلش چاپ می‌شود. آن فایل **دست‌نخورده** می‌ماند و بقیه‌ی فایل‌ها اعمال می‌شوند. در پایان خلاصه می‌دهد: `Done: X applied, Y skipped, Z failed`. اگر همه‌یا‌هیچ می‌خواهید، `-s` بزنید.

| شرایط | نتیجه (فقط برای همان فایل، بقیه ادامه می‌دهند) |
|---|---|
| خطوط diff با فایل نمی‌خواند | `[FAIL]` |
| فایل در مقصد وجود ندارد (diff برای تغییر است) | `[FAIL]` |
| diff می‌گوید فایل جدید، ولی از قبل هست | `[FAIL]`، رویش نمی‌نویسد |
| diff می‌گوید حذف، ولی محتوا فرق دارد | `[FAIL]`، پاک نمی‌شود |
| تغییر از قبل اعمال شده | `[SKIP]` |
| فقط فاصله یا CRLF فرق دارد | اعمال می‌شود، با علامت `(whitespace-tolerant)` |
| تفاوت در جای دیگر فایل (بیرون از بلوک‌ها) | مشکلی نیست؛ جای بلوک با متن اطرافش پیدا می‌شود، نه شماره‌ی خط |
| مسیر ریپو غلط یا ریپو نیست | هیچ‌چیز اعمال نمی‌شود، خطا |
| خط اول مسیر نیست، diff است | هیچ‌چیز اعمال نمی‌شود، خطا |

اگر در یک فایل چند بلوک باشد و یکی نخواند، کل آن فایل `[FAIL]` می‌شود (فایل هرگز نیمه‌کاره نمی‌ماند). فایلی که اعمال می‌شود فقط خطوط مشخص‌شده را عوض می‌کند، نه کل فایل را. برای ایمنی، اول با `-n` (فقط بررسی) اجرا کنید.

## گزینه‌ها

| گزینه | کار |
|---|---|
| `-n`, `--dry-run` | فقط بررسی، چیزی نوشته نمی‌شود |
| `-y`, `--yes` | بدون پرسیدن تأیید |
| `-s`, `--strict` | همه یا هیچ: اگر حتی یک فایل مشکل داشت، هیچ‌چیز اعمال نشود |
| `-b NAME`, `--branch NAME` | قبل از اعمال، branch جدید بساز |
| `-c MSG`, `--commit MSG` | فایل‌های اعمال‌شده را commit کن |
| `-a`, `--archive` | بعد از اجرای کاملاً موفق، `diff.txt` را به `diff.applied-<تاریخ>.txt` تغییر نام بده |
| `-r PATH`, `--repo PATH` | به‌جای خط اول از این مسیر استفاده کن |
| `-u`, `--undo` | آخرین اجرا را برگردان |
| `-h`, `--help`, `-v` | راهنما / نسخه |

### مثال‌ها

```bash
./dw.sh -n                              # اول فقط بررسی
./dw.sh                                 # اعمال (یک بار تأیید می‌گیرد)
./dw.sh -y -b feat/theme -c "Update theme"
./dw.sh -u                              # برگرداندن آخرین اجرا
./dw.sh -u -r ~/code/portfolio          # برگرداندن، وقتی diff.txt بایگانی شده
```

## نکات

- مسیر می‌تواند با `~`، مسیر مطلق، یا حتی مسیر ویندوزی در WSL (مثل `D:\work\site`) باشد. پیشوند `repo:` هم قبول است.
- آخرین اجرا در `.git/dw-last.patch` ذخیره می‌شود (commit نمی‌شود). `-u` همان را برمی‌گرداند. اگر با `-c` commit کرده بودید، برای برگشت از `git reset --hard HEAD~1` استفاده کنید.
- تغییرات commit‌نشده‌ی خودتان دست نمی‌خورد؛ فقط هشدار داده می‌شود.
- فنس‌های markdown و متن‌های اضافه‌ی چت (مثل «Here you go») خودکار نادیده گرفته می‌شوند. فایل با CRLF یا BOM (ذخیره‌شده با Notepad) هم مشکلی ندارد.
- اگر فایل‌هایتان CRLF است و diff فقط در پایان خط فرق دارد، برنامه خودکار با تحمل فاصله‌ها اعمال می‌کند و `(whitespace-tolerant)` می‌نویسد.
- پیش‌نیاز: `bash` و `git`.

## عیب‌یابی

- **`repo folder not found`**: خط اول `diff.txt` را بررسی کنید (بدون فاصله‌ی اضافه یا کاراکتر عجیب).
- **`line 1 ... must be the repo path`**: خط اول diff است، نه مسیر. یک خط مسیر بالای diff اضافه کنید.
- **`patch does not apply`**: فایل شما با نسخه‌ای که diff روی آن ساخته شده فرق دارد. فایل فعلی را برای Claude بفرستید.
- **`no terminal to ask for confirmation`**: در اجرای غیرتعاملی از `-y` استفاده کنید.
